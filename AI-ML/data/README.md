What lives under `AI-ML/data/`, which files are tracked in git, which are generated, which code reads and writes each one, and which external downloads are needed. Paths come from `hawa_ml.settings.Settings` (`DATA_DIR`, `RAW_DATA_DIR`, `INTERIM_DATA_DIR`, `PROCESSED_DATA_DIR`, `EXTERNAL_DATA_DIR`, `CACHE_DIR`, `FIXTURES_DIR`), all relative to `AI-ML/`.

Data provenance and the dataset build are in [AI-ML/README.md](../README.md); file formats are in [CONTRACTS.md §6](../CONTRACTS.md#6-file-contracts).

---

## 1. Layout

| Directory | In git | Produced by | Purpose |
|---|---|---|---|
| `fixtures/` | yes | committed; two files regenerated by scripts | Offline fallbacks and demo inputs |
| `internal/` | yes | engine at run time | Runtime state: effectiveness library, calibration profiles, injected interventions |
| `external/` | no (`.gitignore`) | manual download; `scripts/fetch_all.py` writes `stations.csv` | CPCB CSVs, WorldPop raster, station list |
| `cache/` | no | ingestion clients | HTTP response caches per source |
| `processed/` | no | `scripts/build_dataset.py`, or the first import of the API | Model-ready parquet files |
| `interim/` | no | `scripts/demo_seed.py`, `simulation/device_sim.py` | Simulated telemetry stream |
| `raw/` | no | nothing | Declared in settings (`RAW_DATA_DIR`), never written |

A fresh clone contains only `fixtures/`, `internal/` and this file. Importing `hawa_ml.api.deps` (or starting the API) builds `processed/grid_covariates_500m.parquet` and `cache/osm/delhi_pois.json` if they are missing.

## 2. Tracked files

| File | Size | Read by | Written by | Notes |
|---|---|---|---|---|
| `fixtures/stations_fallback.csv` | 25 rows | `ingestion/openaq.py`, `ingestion/cpcb.py` | — | Delhi CAAQMS stations (`id,name,latitude,longitude,verified`), ids `del_anand_vihar` .. `del_alipur`; used when there is no `OPENAQ_API_KEY` or `OFFLINE_MODE=true`, and as the coordinate lookup for CPCB CSVs |
| `fixtures/bus_routes_delhi.json` | 6 routes, 654 waypoints | `simulation/device_sim.py` via `load_bus_routes()` | `ingestion/bus_routes_osm.py` `generate_bus_routes()` (called by `scripts/fetch_all.py`) | Synthetic corridors between 15 transit hubs with random jitter (unseeded, so every `make data` rewrites the file with different values) |
| `fixtures/sample_requests.http` | 10 requests | humans (REST Client) | — | Example calls for every endpoint against `@baseUrl = http://localhost:8000`; use port 8100 when running alongside the backend |
| `fixtures/demo_scenario.json` | 3 hotspots | nothing in `AI-ML/` | `scripts/demo_seed.py:107` | Demo narrative: hotspots G-052-054 (road dust), G-048-032 (traffic), G-038-044 (open burning), forecast outlook, injected intervention id. Rewritten (timestamp, weekday, intervention id) by every seed and by the test suite |
| `internal/effectiveness_library.json` | 5 records | `causal/effectiveness_library.py` | same module, on every verification | Seeded from `DEFAULT_PRIORS` when missing. `road_dust:water_sprinkler.sample_count` is 80 at HEAD and grows by one per verification call |
| `internal/calibration_profiles.json` | 1 device | `calibration/drive_by.py` | `DriveByCalibrator.fit_calibration()` | Holds `HPM-TEST-CALIB`, created by `tests/test_phase3_twin_sim.py`; `version` and `last_calibrated` change every test run |
| `internal/synthetic_data/known_interventions.json` | 11 records at HEAD | `simulation/interventions.py` (`FleetSimulator` attenuation) | `InterventionManager.inject_default_demo_intervention()` | One record appended per `demo_seed.py` run (including the one inside the test suite) |

**These four files are runtime-mutable state, not static fixtures.** Running `python -m pytest`, `make demo`, `scripts/demo_seed.py`, any verification endpoint (including `GET /interventions/{id}/impact`), `python -m hawa_ml.causal.placebo`, `python -m hawa_ml.pipelines.verify`, or the backend's in-process fallback and integration tests changes them and leaves the git tree dirty. Restore with `git checkout -- AI-ML/data/fixtures/demo_scenario.json AI-ML/data/internal` or run tests in a copy of the directory. `make data` additionally rewrites `fixtures/bus_routes_delhi.json`.

## 3. External data (manual)

| Path | Source | Used by | If missing |
|---|---|---|---|
| `external/cpcb/*.csv` | CPCB CCR / DPCC station exports (for example `del-punjabi-bagh-dpcc-2024-25.csv`), 15-minute or hourly, with headers such as `Timestamp`, `PM2.5 (µg/m³)`, `PM10 (µg/m³)`, `NO2 (µg/m³)`, `CO (mg/m³)`, `SO2 (µg/m³)`, `Ozone (µg/m³)`, `AT (°C)`, `RH (%)`, `WS (m/s)`, `WD (deg)` | `ingestion/cpcb.py` (`build_dataset.py`) | A synthetic 60-day hourly dataset for the 25 fallback stations is written instead |
| `external/worldpop/ind_ppp_2020_1km_Aggregated.tif` (also accepted under `external/worldloop/`) | WorldPop India 2020 1 km unconstrained population count (people per pixel), from [hub.worldpop.org](https://hub.worldpop.org/geodata/summary?id=24777) | `ingestion/worldpop.py` (grid build) | A parametric density (`15000 x exp(-d/0.12) + 1200` per km² around 28.63 N, 77.22 E) is used |
| `external/stations.csv` | Written by `OpenAQClient.fetch_delhi_stations()` | `ingestion/cpcb.py` | `fixtures/stations_fallback.csv` |

CPCB file names are matched to stations by the first token of the station name (for example `anand` in `del-anand-vihar-...`); unmatched files get the station id from the file stem and the Delhi centre coordinates 28.6139 N, 77.2090 E.

## 4. Generated files

| File | Writer | Contents |
|---|---|---|
| `processed/stations_hourly.parquet` | `ingestion/cpcb.py` `process_all_cpcb()` or `generate_synthetic_cpcb_hourly()` | Hourly rows: `timestamp, station_id, station_name, latitude, longitude, pm25, pm10, no2, co, so2, ozone, temperature, humidity, wind_speed, wind_direction` (+ `no, nox, nh3` from real CSVs). Offline build: 36,025 rows, 25 stations, 60 days |
| `processed/grid_covariates_500m.parquet` | `twin/grid.py` `build_delhi_grid(500.0)` | 10,600 cells: `cell_id, row, col, latitude, longitude, population, vulnerability_weight, primary_land_use, road_density_km_km2, nearest_school_dist_m, schools_nearby_count, nearest_hospital_dist_m, hospitals_nearby_count, ward` |
| `processed/grid_covariates_1000m.parquet` | `build_delhi_grid(1000.0)` | 2,650 cells, same columns (used only by tests) |
| `processed/delhi_population_clipped.npz` | `ingestion/worldpop.py` | Clipped WorldPop array and georeference; only when the GeoTIFF exists |
| `cache/openaq/delhi_stations_v3.json` | `ingestion/openaq.py` | Station list from the live API |
| `cache/openmeteo/forecast_{lat}_{lon}_{h}h.json`, `cams_{lat}_{lon}_{h}h.json` | `ingestion/openmeteo.py` | Intended weather and CAMS caches; currently truncated to 15 bytes because pandas timestamps are not JSON-serialisable (see [README §9](../README.md#9-known-issues), issue 6) |
| `cache/firms/fires_last_{days}d.parquet` | `ingestion/firms.py` | Fire points (`latitude, longitude, frp_mw, confidence, acq_datetime`); never expires, so a synthetic file written once stays in use until deleted |
| `cache/osm/delhi_pois.json` | `ingestion/osm.py` | `{schools, hospitals, markets}`; the offline fallback is 96 schools, 40 hospitals and 48 markets around 8 hubs (seed 42) |
| `interim/simulated_telemetry.jsonl` | `FleetSimulator.run_file_mode()` | One telemetry packet per line; `demo_seed.py` writes 40 steps x 14 devices = 560 lines |

Caches are not time-limited. Delete a cache file to force a refetch.
