## 4. `lib/features/`

### 4.1 Conventions the code follows

- **Layers.** Most features have `domain/` (entities, enums, repository interfaces), `data/` (remote sources, mappers, repository implementations, Riverpod providers for them), `application/` (Riverpod controllers and stream providers) and `presentation/` (screens, with `widgets/` for feature widgets). Not every feature has every layer: `inspector`, `school` and `citizen_reports` keep a concrete repository class in `data/` with no domain interface; `settings` has no `domain/` or `data/`; `profile` and `shell` are small.
- **Layer rule.** Presentation never imports `data/` (enforced by `tool/architecture_guard.sh`); it reaches repositories through `application/` providers. Only `data/` and `core/network/` import `package:hawa_api`.
- **One file, several controllers.** Some features group their providers in one file (`inspector_controllers.dart`, `school_controllers.dart`, `reports_controllers.dart`, `air_map_controller.dart`).
- **Fake vs real.** Each remote-source provider picks its implementation from `Env.isFake('<feature key>')`. `USE_FAKE_API` defaults to `true`; `REAL_FEATURES` defaults to `air_map,citizen_air,alerts,school_forecast`. Feature keys used in code: `air_map`, `alerts`, `auth`, `citizen_air`, `citizen_reports`, `citizen_subscription`, `driver_route`, `inspector`, `school`, `school_forecast`, `site` (and `settings` for `PATCH /v1/me`). Fakes live either in a `fake_*.dart` file or as a `Fake*` class inside the remote-source file; all of them call `core/network/fake/fake_backend.dart`.
- **Command-center adapters.** Where the backend already serves a read under a different shape, a `CommandCenter*Source` (or `Http*` source on `CommandCenterApi`) reshapes it into the contract model: `CommandCenterOpenAirSource`, `CommandCenterAlertsSource`, `CommandCenterForecastSource`, `HttpAirMapRemoteSource`.
- **Generated parts.** Files with `part '*.g.dart'` / `part '*.freezed.dart'` need `make gen`; the parts are gitignored.
- **Screens without the conventions.** `safe_route_screen.dart`, `live_operations_screen.dart`, `ward_scorecard_screen.dart` and `missed_machine_screen.dart` are self-contained mock screens: hard-coded data, hard-coded English, no controller, styled with the legacy `lib/app/theme.dart`.
