# HawaCommand — Documentation

Blueprint for building **HawaCommand**: an AI command centre that finds, forecasts and fixes Delhi's pollution hotspots, and proves every fix worked. (Environmental Hacks 2026 · Bharat Builds Tour · Track 01: Air.)

These docs started as a blueprint derived from [`HawaCommand_Proposal.pdf`](../HawaCommand_Proposal.pdf) (Proposal v3; section references like **§9.4** point to that PDF). They have since been reconciled with the code at commit `a33e043` (2026-10-10). Where the code and a doc disagree, the code wins and the doc is the bug.

**Status words used everywhere:** **Implemented** (works as described), **Partial** (works, with the gap named), **Stub/Mock** (fixtures, hard-coded or synthetic data), **Planned** (designed, not in code). Design sections that describe the target system (Kafka, PostGIS, Redis, WebSocket, Strands agents, CDK, CI) are kept as the plan and labelled **Planned**.

## Ground rules for every team

1. **Contracts first.** Names in [CONTRACTS.md](CONTRACTS.md) are the law. To change one, update CONTRACTS.md and `backend/contracts/` in the same PR and tag all four leads. The web console's zod schemas (`frontend/src/contracts/`) and the app's OpenAPI snapshot (`app_frontend/openapi/openapi.json`) must follow.
2. **Honesty rule.** One real pod, a simulated fleet, a real pipeline. Anything with `is_simulated = true` shows a "Simulated" badge.
3. **Uncertainty everywhere.** No model output reaches a screen without its confidence, P10/P90 or CI.
4. **The optimiser decides, agents explain, officers approve.** Nothing dispatches without human approval.
5. **Cut rule.** If behind, drop wind advection, Citizen Eyes and the school scheduler. Never drop the What-If screen and causal verification.
6. **Docs follow code.** When you change behaviour, update the component README and the matching doc in this folder in the same PR, including the status word.
